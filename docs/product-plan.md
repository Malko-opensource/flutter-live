# Flutter Live 제품 기획서

2026년 11월 2일 확정. Flutter 행사에서 발표를 보거나 서로 다른 언어로 대화할 때 사용하는 macOS 실시간 통역 앱이다. 두 언어를 한 번 선택하면 발화 언어에 따라 반대쪽 언어로 통역한다. 대화 기록 목록과 저장·조회 기능은 제공하지 않는다.

## 사용 경험

### 자막 오버레이

다른 사람의 프레젠테이션 위에 작은 Dash와 현재 번역문을 띄운다. 설정 창은 닫아도 세션과 자막 창은 유지된다. 반투명 어두운 자막 바에 번역문을 크게, 원문을 작게 표시한다. Dash는 바 왼쪽에 배치하며 발표 내용의 가림을 최소화한다. 자막 창은 드래그로 이동하고 메뉴바에서 다시 열 수 있다. 기본적으로 번역 음성은 꺼 발표 음성과 겹치지 않게 한다. 사용자가 음성을 켤 수 있다.

### 대화 화면

대면 대화에 사용할 전용 화면이다. Dash와 현재 발화의 원문·번역문을 크게 표시한다. 한국어와 영어처럼 설정한 두 언어 사이에서 방향을 자동으로 바꾼다. 이전 발화를 쌓는 채팅·기록 UI는 없다. 기본적으로 번역 음성을 켜며 음량·일시 정지·종료를 제공한다.

### 공통 설정

- 서로 다른 두 언어 선택. 첫 기본값은 한국어와 English.
- 마이크 또는 시스템 오디오 입력 선택. 첫 구현은 단일 소스이며 동시 믹싱은 후속 단계다.
- 출력은 macOS 기본 오디오 장치. 장치별 선택은 후속 단계다.
- 세션 시작 전 API 키와 사용 가능한 Live 모델을 설정한다. 키는 실행 중 메모리에만 보관한다.
- 입력 소스·언어·모델은 세션을 종료한 상태에서 변경한다. 표시 모드는 세션 중에도 전환할 수 있다.
- 메뉴바에서 창 열기, 자막 표시, 일시 정지·재개, 세션 종료, 앱 종료를 수행한다.

## 최신 캐릭터 결정 — 2026-11-03

2D Dash를 현재 앱 캐릭터로 사용한다. 단순 색면 버전은 품질 피드백으로 폐기하고, 얼굴·의상·소품 접촉을 함께 그린 완성형 일러스트로 재제작한다. 원형 눈과 짧은 새의 팔다리는 유지하며, 표정·옷의 겹침·곡선 형태를 살린다. 기본 의상은 한복이며 설정에서 갓·두루마기, 단청 무대복을 선택한다. 한복과 갓은 선글라스 없이 맑고 둥근 눈, 단청은 선글라스를 유지한다. 모자를 쓴 갓 버전은 정수리 깃이 보이지 않는다.

Blender에 분리된 2D 파츠·본·키프레임을 보관하고, 앱은 그 리그에서 렌더한 투명 프레임을 재생한다. Idle·Listen·Speak·Wave·Celebrate·Reconnect·Sing·Megaphone 8가지 동작을 사용한다. 일반 발화는 손에 든 마이크와 음표, 큰 발화는 오른쪽을 향한 확성기와 바깥으로 퍼지는 파동이다. 이 결정이 아래 초기 3D 제작 기록보다 우선한다.

## 디자인

승인 시안은 [두 모드 디자인](design/approved-modes.png)을 기준으로 한다. Flutter 블루, 밝은 macOS 표면, 어두운 반투명 자막 바를 사용한다. 이후 확정한 캐릭터 방향은 **K-pop 무대 의상을 입은 Flutter Seoul Dash**다. 공식 Dash의 둥근 몸통, 짧은 날개·다리·발가락과 곧은 부리를 유지한다. 사용자가 제공한 Stray Kids 사진의 검정·보라색 의상, 실버 체인·지퍼, 주황색 포인트를 짧은 새 전용 조끼로 재구성한다.

Blender 원본에는 메시, 하이폴리 조형, 리토폴로지 케이지, UV, 노멀 맵, PBR 재질, 9개 본, 눈 표정 모프와 여섯 애니메이션이 있다. Idle·Listen·Speak·Wave·Celebrate·Reconnect를 앱 상태에 연결한다. 첫 앱 통합은 이 실제 모델에서 렌더링한 12 fps 투명 아틀라스 방식이다. `.blend`와 애니메이션 `.glb`도 제공하며, 앱 자체가 실시간 3D로 렌더링한다고 표현하지 않는다. 동작 줄이기 설정을 존중하고 자막 창이 숨겨지면 네이티브 애니메이션 타이머를 멈춘다. [제작 기준](../art/dash_seoul/BRIEF.md)과 [제작 결과](../art/dash_v2/README.md)를 참고한다.

2026-11-02 캐릭터 수정: 사용자가 제공한 6면 참조를 기준으로 작은 초록 테두리 눈, 얇은 얼굴 패치, 짧은 날개·발, 매끈한 몸통으로 v2를 재제작했다. 기본형과 의상을 분리해 비교할 수 있도록 했다.

| 통역 중 | 번역 자막과 선택적 음성 | 현재 번역문 갱신 |
| 일시 정지 | 일시 정지됨 | 캡처·재생 중지, 재개 시 새 연결 |
| 재연결 | 연결 재시도 중 | 지수 백오프, 최대 2초 입력 버퍼 |
| 실패 | 원인과 재시도 안내 | 무한 재시도하지 않고 캡처 종료 |
| 미리보기 | 디자인 미리보기 | 샘플 문구만 표시, 캡처·API 사용 없음 |

인터럽트 이벤트를 받으면 Flutter 재생 큐와 네이티브에 예약된 오디오를 함께 비운다. 종료·일시 정지·오류 때에도 동일하게 처리한다. 재연결 시 오래된 소리를 무제한 일괄 전송하지 않고 제한된 최근 버퍼만 순서대로 보낸다. 복구 후 20 ms마다 최대 4청크를 보내 밀린 입력을 따라잡는다. 연결 복구 중 누락이 발생할 수 있음을 상태 문구로 알린다.

## 기술 설계

Flutter가 화면, 세션 상태, 현재 자막, WSS, 제한된 PCM 큐를 소유한다. Swift/AppKit 브리지는 메뉴바, 비활성 플로팅 패널, AVAudioEngine 캡처·재생, ScreenCaptureKit 시스템 오디오를 담당한다. 네이티브 콜백은 Flutter 메인 스레드로 전달한다.

- 입력: PCM signed 16-bit little endian, mono, 16 kHz. 20 ms 청크는 640바이트다.
- 출력: 서버 MIME의 샘플 레이트를 확인한다. 초기 구현은 24 kHz PCM16 mono를 지원한다. 입력과 출력 레이트를 혼동하지 않는다.
- 오디오 큐: Flutter 순환 버퍼에 상한을 두고 네이티브 예약량에도 상한을 둔다. 인터럽트 시 세대 번호로 과거 오디오를 폐기한다.
- Live 연결: setup JSON, 입력·출력 transcription, realtimeInput.audio, serverContent의 모든 오디오 part, interrupted, turnComplete, 세션 재개 핸들, goAway를 처리한다.
- 자막: API의 텍스트 조각을 현재 발화에 결합한다. interim 원문은 교체하며, 확정 텍스트와 구분한다. 임의의 과거 단어 수정 기능을 API의 보장으로 가정하지 않는다.
- 마이크: NSMicrophoneUsageDescription과 App Sandbox의 com.apple.security.device.audio-input을 사용한다.
- 네트워크: com.apple.security.network.client를 선언한다.
- 시스템 오디오: macOS 13 이상 ScreenCaptureKit을 사용하고 자기 앱의 오디오를 제외한다. 화면 녹화/시스템 오디오 접근 승인이 필요하다. 별도 가상 오디오 드라이버는 첫 구현에 설치하지 않는다.
- 기록: 로컬 파일·분석 로그에 발화·API 키를 저장하지 않는다. 공급자 측 데이터 처리는 별도 정책 확인 대상이다.

## 원래 요구사항에서 정정한 항목

원래 목소리를 그대로 복제하는 기능은 현재 범위에서 보장하지 않는다. 모델이 제공하는 음성을 사용한다. 무지연 동시통역을 보장하지 않으며, 실제 발화부터 자막·음성 출력까지의 지연을 측정해 판단한다. 20 ms 전송 주기만으로 모델 응답 지연이 없어지는 것은 아니다. 언어 자동 감지는 모델 지시로 구현하며, 짧은 발화·언어 혼용·동시 발화의 정확도를 행사 리허설에서 검증한다.

## 구현 단계와 인수 기준

1. 앱 기반과 승인 UI: 두 모드, Dash, 현재 자막, 메뉴바, 미리보기. 기록 목록이 없어야 한다.
2. 입력과 권한: 마이크/시스템 오디오를 실제 장치에서 16 kHz PCM으로 확인. 거부 시 복구 안내, 중지 후 캡처 해제.
3. Gemini 연결: 실제 키로 setupComplete, 양방향 언어 전환, 자막·음성 확인. 오디오와 자막이 한 이벤트에 있어도 모두 처리.
4. 안정화: 재연결, 일시 정지 중 재접속 금지, 인터럽트 큐 폐기, 버퍼 상한, 긴 발표, 발표 앱의 전체 화면·다중 모니터 검증.
5. 배포: Xcode Release 빌드, 서명·공증, 실제 행사 음향에서 피드백/에코와 화면 공유 노출 확인. App Store 출시는 별도 검증 단계.

현재 구현·검증 결과는 [개발 현황](implementation-status.md)에 따로 기록한다. 이 기획 확정은 API 실측이나 배포 완료를 의미하지 않는다.

### 발화 반응 동작

사람이 말할 때 대쉬는 스탠드 마이크를 짧은 날개로 잡고 노래하듯 부리와 몸을 움직인다. 대화 화면과 자막 오버레이 모두 같은 Sing 동작을 사용한다. 발화가 멎으면 기존 대기/통역 동작으로 돌아가며, 짧은 쉼 때문에 소품이 반복해서 나타났다 사라지지 않게 전환을 완충한다. 새의 신체 비율과 현재 눈 디자인을 유지한다.

공연 동작은 몸을 기울이고 양 날개로 대각선 스탠드를 잡는 자세로 강화한다. Sing에는 음표·박자선, Wave에는 반짝임, Celebrate에는 별·색종이를 캐릭터 주변에 배치한다.

### 큰 소리 반응

입력 음량이 설정 기준을 넘으면 대쉬가 빨간 확성기를 들고 소리 파동을 내보이는 동작으로 전환한다. 기본 진입 기준은 −18 dBFS/100ms, 해제는 6 dB 낮은 기준과 450ms 유지다. 사용자는 설정에서 −36~−6 dBFS 범위로 민감도를 조절한다. 실제 공간의 소음 데시벨이 아닌 녹음 신호 기준이며 마이크와 시스템 오디오에 동일하게 적용한다. 모든 동작에서 짙은 선글라스를 유지한다.
